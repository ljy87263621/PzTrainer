# 原版俯视角模型效果检修（beta.9）

## 本次证据

本机修改器日志显示实体和骨骼正常，原版有效模型捕获一直为零。游戏 `console.txt` 则记录了大量 `FBORenderObjectOutline.render` 空对象异常；这类游戏自身捕获的异常不会显示在修改器 Capture 字段。

对照游戏类后确认两个独立缺口：通用主线程调用队列在世界帧构建前执行，随后 `SpriteRenderState.prePopulating()` 会清空渲染命令；额外模型也没有建立自己的 `ModelCameraRenderData`。另外，实际生产捕获／重放的 GPU 用例复现了缩放后的视口错配。此前仅验证渲染数据构造和独立合成器，未覆盖这个组合。

旧采集路径还会从修改器绘制线程调用轮廓注册和 alpha setter，涉及游戏自己的轮廓集合／状态。该写入已删除，以消除本工具对游戏主线程轮廓状态的竞争；不能据此断言所有其他 Mod 的错误都会消失。

## 修改后的链路

1. 与方框、骨骼 ESP 一样，从只读快照获得实体身份和可见性。
2. C++ 仅发布实体身份、分类和标记，Java 保留不可变选择，500 ms 后失效。
3. 在游戏 `IngameState.renderFrameInternal(int)` 中，世界绘制之后、`ModelOutlines.endFrameMain(int)` 之前调用额外提交。该位置已完成帧初始化，命令会随当前世界帧交给绘制线程。
4. 在游戏主线程准备每模型的光照、姿态、模型槽引用和 `ModelCameraRenderData`；在绘制线程使用对应相机，并在正常／异常退出时恢复先前相机。
5. 生产 OpenGL 捕获按同一实体身份筛选，保留主角遮罩和独立填充／边缘可见性。重放使用 UI 大小的效果纹理视口，不再把放大的世界缓冲视口应用第二次。

不再修改角色自身 alpha，也不再要求物件轮廓的 UI 时钟就绪。ViewPoint 的批次筛选和第一人称帧结束前绘制路径保持原实现。

## 验证范围

- `scripts/test-native-capture.ps1`：实际游戏 IngameState 字节码的准确回调位置与校验；生产 JNI/JVMTI 钩子安装；真实 MinHook 捕获和重放；直接编译本机游戏的 `aim_outline_solid` 顶点／片元着色器。受控网格覆盖僵尸／玩家、仅填充／仅边缘／组合、主角重叠遮罩、未选中对象、1／1.5／2 倍世界缓冲尺寸和输出 FBO 恢复。
- 缩放回归在修复前于 1.5 倍尺寸复现边缘像素为零，修复后上述组合通过。
- `NativeModelCaptureTest`：实际游戏类的空每玩家数据构造、模型槽归属及引用释放，模型相机位置／角度／模式和正常／异常恢复。
- `scripts/test-model-colour.ps1` 包含上述检查，并继续运行 ViewPoint 原有 API、GPU、第一人称帧钩子及状态恢复回归。
- `scripts/test-esp-read-only.py` 防止实体采集重新引入旧轮廓写入和物件 UI 时钟依赖。

这些检查不依赖正在运行的用户存档，也未在用户当前进程内热替换 DLL 或改写游戏对象集合。真实角色全套服装、存档中的视觉效果和错误计数是否停止增长仍需更新后实测。

## 更新与复测

请保存存档并完全退出游戏，再通过 beta.9 启动器加载。新 helper 和新的帧回调需要重新载入；仅重载 Lua 或在旧进程重复载入不能清理已经形成的旧轮廓状态。

先在原版俯视角分别启用全身上色、边缘发光及二者组合，再缩放、与主角重叠和往返第一人称。关闭逐项视野检测时，仍按当前已加载且在距离内的对象显示；启用时按游戏实际可见性筛选。

若仍未显示，修改器日志会增加 `worldCallbacks`（世界帧回调次数）、`queuedModels`（最近提交模型数）、`renderedModels`（绘制回调次数）和已有捕获／着色程序统计。游戏原始异常仍可直接读取 `%USERPROFILE%\Zomboid\console.txt`，无需安装错误查看 Mod。
