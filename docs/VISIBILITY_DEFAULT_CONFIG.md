# 实际可见检测、模型采集与默认配置（2026-10-15）

## 使用方式

- 视觉 ESP 的僵尸、玩家、动物、载具卡片增加“逐项视野检测”。点击旁边的更多按钮展开；方框、名称、距离、骨骼、血条、方向箭头、管理员标记、车辆详情、发动机条、全身上色和边缘发光按适用对象分别设置。
- “仅实际可见”默认关闭。关闭时保留已加载对象和设置距离内的显示；开启时使用游戏的实际可见状态。角色使用游戏 `isVisibleToPlayer`，载具和物资使用所在格子的 `isCanSee`，不使用旧的“朝向内”近似判断替代。
- 全身上色和边缘发光仍可分别开关，二者的可见性检测也独立。例如可仅过滤方框和上色，保留不可见对象的骨骼与轮廓。
- Lua 物资 ESP 增加“名称仅实际可见”“图标仅实际可见”。二者默认关闭，在原版与 3D 投影下采用相同的可见性规则，并在绘制时刷新，避免扫描缓存留下过时标记。
- 设置 → 配置管理：点击配置名前的圆形按钮指定默认配置。蓝色圆点表示已指定；再次点击取消。点击名称仍只选择配置。指定默认不会立即加载。
- 下次注入后，进入存档、JNI 和 Lua 注册接口就绪时自动加载一次。自动加载结果显示在配置管理上方，失败也会写入 `pztrainer.log`；不会随意改载其他配置。删除默认配置或更换配置目录会清除指定。

## 实现变更

原版不再把共享着色器中的 RGB 当成对象身份。选中的角色在游戏主线程准备模型数据，经渲染队列提交带有明确身份作用域的采集通道；没有身份的普通人物绘制不会参与重放。作用域在异常退出和嵌套调用后恢复，重放前还会校验对象仍在当前快照中。已加载但尚未添加到模型管理器的选中角色通过游戏原有 `ModelManager.Add` 准备模型。

原版还单独采集主角的轮廓作为排除遮罩。上色和边缘先绘入私有目标，再在合成时跳过主角覆盖的像素，防止正确采集的僵尸叠加层在二者重合时覆盖主角。此遮罩只用于排除自身，不会把自身加入上色对象。

ViewPoint 模型绘制的外部 GL 状态增加 Alpha Test、Stencil Test、Color Logic Op 和 Rasterizer Discard 的隔离与恢复。在兼容上下文 GPU 回归中已复现“模型提交成功但最终像素被 Alpha Test 拒绝”，并验证修正。填充与轮廓使用分别按对象过滤的绘制选择器。

## 配置兼容

配置格式升级为版本 21；旧的二进制设置结构大小保持不变，可见性选项放入新增尾部。旧配置中缺失的新选项关闭；已有功能值、Lua 控件值和 3D 设置保留。成功解析后先保留 `.v版本号.bak` 原文件，再通过临时文件原子替换。版本 21 中缺失的可见性条目也会补为关闭并写回。损坏、截断或无法识别的未来版本不会覆盖原文件。

默认配置名称保存在 `preferences.ini`，与配置内容分开；更新默认指定和保存配置均使用临时文件替换，失败会保留原文件。

## 验证范围

- C++：逐项可见性策略、配置版本 20 → 21、版本 21 往返、缺项补齐、Lua 值保留、原文件备份、截断文件拒绝、默认指定/取消/跨进程重读、自动加载一次和删除后清除。
- 用户的 `111`、`222` 仅复制到临时目录进行解析和升级回归，测试不改动真实配置。
- JVM/GPU：对象归属、自身排除、未可见角色的采集选择、身份作用域清理、真实安装版 ViewPoint API/着色器、透视与 Panini 投影、单独填充/轮廓、逐层可见性、继承 GL 测试状态及恢复。
- Lua：完整脚本在游戏 Kahlua 解释器中验证缩放、自动/手动投影、逐项可见性及缓存刷新。

本机验证不等于存档内的实测。目前没有正在运行的游戏可完成现场验证，原版遮挡下的实际模型提交和 ViewPoint 第一人称效果仍需在游戏中验收。显示范围受已加载对象、可用模型和设置距离限制；不会为未加载的地图区域生成对象。

建议验收顺序：原版仅开僵尸上色时与僵尸重叠；在遮挡前后分别切换填充和轮廓的可见性；ViewPoint 第一人称分别测试填充、轮廓及同时开启；保存并指定默认配置后重新注入检查自动加载。
