# 模型上色修复与独立边缘发光

本地验证构建，2026-10-15。保留物资 ESP、人物热色材质和可移动家具生成器扩展。

## 更新后使用

完全退出已经注入修改器的游戏，用新构建的 `pztrainer_launcher.exe` 启动并注入。本次更新包含 C++ 本体与内嵌 Java 渲染辅助包，重新加载 Lua 不会更新这些代码。

在 ESP 的「僵尸」或「玩家」分类开启对应实体 ESP。模型设置现在提供两个独立的自绘开关：

| 全身上色 | 边缘发光 | 显示效果 |
|---|---|---|
| 开 | 关 | 只绘制所选上色材质 |
| 关 | 开 | 只绘制轮廓外的边缘光，内部保留游戏原来的显示 |
| 开 | 开 | 同时显示材质和边缘光 |
| 关 | 关 | 不绘制这两种效果 |

全身颜色和边缘颜色分别配置。上色效果仍可选彩色热能、白热和原有材质。选中具体材质会开启全身上色；关闭开关会选择 Disabled，边缘开关不受影响。本次会话内重新打开全身上色会恢复之前选择的材质。关闭状态和边缘设置沿用现有配置字段保存，历史配置布局和枚举编号不变。

beta.8 起，使用 ViewPoint 时会自动匹配当前渲染器，无需手动兼容／3D ESP 开关。3D 材质使用当前模型批次和相机，不依赖原版俯视角的模型捕获初始化。第一人称自身模型不参与上色，以免遮挡镜头；其他玩家、僵尸与其衣物按对象归属匹配。

## 修复内容

### 原版重叠误上色

原版重放函数在没有捕获标记时，会用模型原点是否落入实体屏幕包围盒来猜测对象，并优先匹配僵尸。玩家与僵尸重叠时，未标记的玩家模型会被归入僵尸组。

现在捕获和重放都要求模型具有本体为实体写入的明确标记，删除了位置猜测分支。未标记玩家不会因为与僵尸重叠而继承僵尸材质。

### ViewPoint 第一人称路径

旧 3D 上色受原版捕获上下文和原版初始化状态限制，同时依赖模型快照里的轮廓颜色标记。现在 3D 路径直接进入 ViewPoint 辅助渲染：从当前模型实例、衣物父实例的所属对象身份匹配当前快照，不需要轮廓标记。失去归属、快照里不存在、身份冲突和第一人称 SELF 的人物模型都跳过。

3D 材质在私有帧缓冲中绘制，再按最终相机投影合成到画面。透视相机与 Panini 映射有实际 GPU 像素检查；Panini 检查以本机 mod 的 `Panini.toFrame` 为对照。

### 独立边缘

边缘从模型透明裁切后的轮廓遮罩生成。合成时膨胀轮廓并减去内部，而不是把放大的整个人物当作边缘绘制。因此全身上色关闭时，边缘光不会涂满人物内部。原版和 Java 路径使用同一份合成 GLSL，预览也取消了材质自带的隐式边缘光。

## 验证与范围

- 修改前，原版重放函数在未标记玩家与僵尸重叠时的回归用例失败；修改后正确排除玩家，保留明确标记的实体分组。
- C++ 生产重放入口测试覆盖没有原版捕获上下文、没有当前 GL 上下文的 ViewPoint 转发，以及只上色、只边缘、同时开启、旧手动值忽略与游戏状态限制。
- ViewPoint 实际模型实例测试覆盖所属对象、衣物父实例、无轮廓标记、未跟踪对象、身份冲突与父链循环。
- 隐藏 WGL / GLFW 上下文中的实际帧缓冲验证只边缘时内部不改色、仅上色时轮廓外无光、组合模式、透视相机、Panini 映射、SELF 排除、热色和白热切换。
- GL 状态检查覆盖程序、读写帧缓冲、颜色写入掩码、清屏颜色、纹理与采样器、间接绘制缓冲、视口、深度、剔除、裁剪和混合状态。
- 热色材质 GPU 回归、物资 ESP 62 项 Lua 检查通过；构建与分发资源一致性另行校验。

未进入实际游戏存档操作 UI 或复现用户报告的第一人称画面，也未验证全部服装、姿态和大量实体下的帧率。这是针对已查明代码问题的修复与自动化验证，不代表全部实机场景验收通过。

复现主要验证：

```powershell
.\scripts\test-model-colour.ps1 -GameRoot '<ProjectZomboid 安装目录>' -JdkRoot '<JDK 目录>' -ViewpointJar '<Viewpoint.jar 路径>'
```

便携包内嵌自有渲染资源，用户无需安装 Python、JDK 或额外 C++ 运行库。
