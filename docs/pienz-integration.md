# PienZ 功能整合记录

目标仓库：PzTrainer，基于 `3751883`；参考用户提供的 `PienZ Source FINAL_[unknowncheats.me]_.zip`。

参考 ZIP SHA-256：`c22b3a7634ad4d9abbdd4e85401b4105862d785e8919540a809da410e6efdd942`。

入口按用途分布：**角色状态**（角色保护、装备维护、武器强化）、**载具控制**、**世界交互**、**角色创建**。功能按会话、权限和目标状态决定是否可用，置灰项悬停显示原因；取消原来的整体离线限制。服务器攻击、封禁绕过及针对其他玩家的 Troll 操作未移植。Common Sense、Better Safehouse、辐射模组扩展按用户确认的范围排除。

世界交互保留僵尸与环境、尸体与容器操作，已按要求删除格子交互和动物与音效的菜单及执行入口；角色创建分为世界与职业、特质与技能、角色外观、预设管理。使用项目自绘导航、标签、开关、数值条、颜色选择器，以及新增的动画按钮、输入框和可筛选下拉选项。侧栏可滚动，底部用户信息保留固定位置。

## 行为与原参考的区别

- 无敌模式参照 PienZ 的连接标志实现：在连接服务器前开启，将 Godmode 位加入 ConnectPacket；收到 ConnectedPacket/ExtraInfo 回传后按参考实现协调客户端标志。已发送连接请求时锁定开关，并提示先断开再更改；不把发出请求当作服务器确认。
- 负重修复同时作用于人物最大负重读取和本机角色主背包有效容量。保留现有最大负重倍率，主背包容量按 PienZ 放宽；其他容器不受影响。原版 PlayerDamage 在主线程定期同步最大负重，忽略同步回传值造成的倍率重复叠加；关闭后恢复。
- 新增 player 目录与 player_overrides JNI/JVMTI 桥接，仅改写上述目标方法。只有独立的 `pztrainer-player-overrides.jar` 加入系统类加载器搜索路径，使原版游戏类能解析回调；扩展与 Lua 留在原有 URLClassLoader 的 `pztrainer-lua-bridge.jar` 中，避免延迟加载时包内类被分到不同加载器，不修改磁盘上的游戏 JAR。两个 JAR 均内嵌在 DLL 中。

- 世界批量操作限定当前楼层与明确的半径。联机按 PienZ 的同步方式适配当前游戏 API：背包耐久使用 SyncItemFields，水桶使用 ItemStats，衣物使用 syncVisuals；车辆通过原版 vehicle 命令请求维修、胎压、加油和启动引擎。
- 联机容器操作分批发送移除、clearContainerExplore、RequestItemsForContainer 请求；每 100 ms 最多处理 4 批，每批至多 128 件物品。重刷会跳过没有房间定义的室外容器，避免调用原版服务器脚本的空房间路径。连接或角色变化时取消未执行队列。反馈区显示已提交数量，不把提交请求当作服务器确认。
- 联机僵尸 AI / 击杀仅处理 onlineId 有效且 isLocal() 的僵尸，通过 ZombieSimulationReliable 分批同步，每批不超过 300 个。全局“僵尸不攻击”开关没有覆盖远端模拟的同步路径，联机置灰；无肌肉酸痛需要 CanModifyBodyStats，隐身需要 ToggleInvisibleHimself，否则置灰。
- 水桶补水遍历子背包，跳过含非水液体的桶；保留原液体成分，不把脏水自动变为净水。
- 暴击与近战距离只作用于当前主手武器；换武器/关闭时恢复原属性。AI 与隐身也记录原值。维修、清洁、杀死或删除不是可逆操作。
- Instant 使用 PienZ 的 Bullet 签名/状态恢复辅助代码，C++20 仅用于两个新增物理源文件。游戏导出、调用点及刚体辅助方法的签名全部匹配才启用。物理状态写入发生在游戏物理步进前后；需要本地驾驶、引擎运行、本机物理模拟权、1–4 轮且没有拖挂的车辆。速度不超过 70 km/h，联机时再取服务器 speedLimit 的较小值。菜单或文字输入时禁止移动，关闭/换车/失去控制权/离开会话时恢复原物理标记。联机移动仍由游戏车辆同步与服务器检查处理。
- 创建编辑调用原版界面的回调；职业免费特质不能单独移除，互斥特质遵循原版规则。出生技能覆盖在原版 `initPlayer` 返回后写入 Integer 类型的 XP map，进入游戏或更换角色描述对象后撤销回调；这组技能覆盖不写入原版预设。
- 创建编辑不自动跳过游戏的创建步骤，也不接入 TIYL 等模组的创建流程。预设保存打开原版命名窗口，需暂时关闭 DLL 菜单后输入名称。
- 原版联机角色创建也可编辑；联机时世界名称和种子由服务器控制，对应输入框和按钮置灰。出生技能覆盖不会因为客户端模式而提前清除。
- 持续开关和击杀范围随现有配置文件保存（格式 16），旧版配置仍可加载并将新增选项置为默认关闭。`extensions.*` 已接入现有 Lua 功能注册表。单次世界操作不写入配置，也不会在载入配置时重放。

## 源码结构

- `trainer/src/java/pztrainer/extensions/`：按装备、僵尸、车辆、世界、角色创建划分；普通修改通过游戏 `MainThread` 队列执行。
- `trainer/src/bridge/extension_bridge.*`：通过现有内嵌 JAR 的 class loader 加载扩展、提交命令、读取结果；Java 资源仍内嵌在一个 DLL 中。
- `trainer/src/features/vehicle/`：底层物理签名检测和步进回调；`bullet_vehicle_ghost.*` 改编自参考压缩包同名文件，保留检查/恢复实现。
- 车辆物理请求使用线程 ID 所有权校验，不使用 C++ 静态 TLS。启动器手动映射 DLL 时不会注册这类 TLS；旧实现会在普通车辆更新回调中读到无效请求指针，导致原生访问冲突。
- `trainer/src/ui/character_status.cpp`：角色保护、装备维护和武器强化。
- `trainer/src/ui/vehicle/`、`world/`、`creation/`：对应领域的独立页面。
- 新增页面使用与辅助瞄准页一致的双列紧凑卡片，标题位于卡片外；操作反馈放入对应列。侧栏隐藏滚动条，保留鼠标滚轮滚动。
- `trainer/src/ui/controls/`：复用的自绘动画控件；`ui/extensions/`：扩展功能的命令、开关及反馈绑定。
- `ExtensionAccess.java`：会话可用性与禁用原因；同一份快照驱动 UI 置灰，主线程执行前重新检查。`NetworkTools.java`、`ContainerOperations.java`：网络同步与分批容器操作。

## 构建与检查

需要 JDK 25、当前游戏 `projectzomboid.jar`、Visual Studio v145 和 Windows SDK。先生成 Java 资源，再构建 DLL；启动器会嵌入刚构建的 DLL。

```powershell
.\scripts\build-java-bridge.ps1 -JdkRoot '<JDK 25 目录>' -GameRoot '<游戏目录>'
.\scripts\test-extensions.ps1 -JdkRoot '<JDK 25 目录>' -GameRoot '<游戏目录>'
msbuild .\trainer\pztrainer.vcxproj /m /p:Configuration=Release /p:Platform=x64
msbuild .\pztrainer_launcher.vcxproj /m /p:Configuration=Release /p:Platform=x64
```

已完成：Java 对本机游戏 JAR 编译、x64 Release DLL/启动器编译、16 项角色创建 Kahlua 模拟测试、27 项会话权限策略检查、物理碰撞标记计算与损坏签名拒绝测试、本机 PZBullet64.dll 的离线签名验证。实际 UI 源码已在离线 ImGui 绘制环境中检查卡片、分组、下拉列表、颜色选择器与滚动区域。

车辆崩溃回归：`scripts/test-vehicle-ghost-mapper.cmd` 使用启动器实际的 ManualMapImage 加载探针 DLL，执行生产车辆回调代码；覆盖已有线程、新线程、无请求的原版回调、跨线程隔离、嵌套请求拒绝、启用/恢复/取消，并确认未污染宿主 TLS。探针模拟车辆数据和原版函数，不代表游戏内驾驶验收。

轮数解码修复：本机 PZBullet64.dll 的 getOwnVehiclePhysics 将轮数编码为 `轮数 + 0.1f`，setOwnVehiclePhysics 截断转为整数。按原版及 PienZ 的解码方式检查 1–4 轮，保留回写数组的原始编码，避免将四轮车的 4.1 误判为超过 4 轮。VehiclePhysicsStateTest 覆盖编码轮数、无效数据、旋转校验及传输数据不被校验修改。

尚未完成游戏内双客户端验收。编译、模拟测试和离线 UI 绘制不证明服务器接受请求、远端可见、实际驾驶或存档重读成功。待验收：进退联机会话及权限变化时置灰/恢复、物品同步与重连后持久性、本机模拟僵尸的状态恢复、Instant 开关/下车/退出、每类单次操作、实际创建角色后技能与外观。新增页面内容以中文显示。

玩家接口验收：已对本机游戏 JAR 验证五个目标类的字节码转换、重复转换及开关位保持；独立 JVM 使用生产 C++ 安装逻辑完成实际 JVMTI 重转换和系统类加载器解析，并执行原版方法验证负重/容量、同步回传不重复叠加、其他玩家隔离、关闭恢复和连接包无敌锁定流程。尚未完成双客户端实战验收。

主菜单类加载回归：先用旧的整包追加方式复现 `IllegalAccessError`，再验证分包后“扩展先加载”和“玩家接口先加载”两种顺序。两种顺序均执行主菜单无角色状态的扩展更新，遍历桥接 JAR 内全部类确认仍由原 URLClassLoader 加载，且系统加载器无法加载这些类。旧 DLL 已注入的游戏必须完全退出后重启，再注入新版；重复注入无法撤销旧进程已加载的类。

负重会话识别修复：参照 PienZ 的 `ReadConnectedClient`，使用 `GameClient.instance.connected` 和连接对象判断客户端连接就绪。此前误用由服务器设置的 `UdpConnection.fullyConnected`，使已进入游戏的存活角色仍被置灰。提示现已区分连接未就绪、角色未进入、已死亡和非本机角色。独立 JVM 先复现旧条件错误，再运行真实负重更新方法，覆盖客户端已连接但服务器标志为 false、开启负重、断开连接、连接对象缺失、死亡/远端/空角色、单机启停恢复及服务器进程排除；联机发包效果仍需游戏内验收。
