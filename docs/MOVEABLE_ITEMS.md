# 可移动家具物品列表扩展

本地验证构建，2026-10-14。物品生成器补充了能拾取到背包的家具图块物品，包括办公隔间、隔板、椅子和其他具有 `IsMoveAble` 属性的部件。

## 使用

1. 完全退出已注入修改器的游戏，用本次构建的 `pztrainer_launcher.exe` 启动并注入。列表和生成逻辑属于 C++ 本体，因此需要更新启动器内嵌的 DLL。
2. 进入单机存档，打开物品生成器，选择「游戏原生」生成方案，点击「刷新物品列表」。刷新结果会分别显示普通物品和家具图块物品的数量。
3. 分类选择「家具」或「全部」，搜索「隔板」「隔断」「隔间」或 `cubicle`。游戏实际显示名称可能是「蓝色隔间」「灰色隔间」等；别名搜索会匹配这类办公隔间部件。
4. 按名称后的朝向标记及完整图块类型选择部件，然后生成到背包。由多个部件组成的家具仍遵循游戏自己的拼装规则，生成单件不会自动补齐整套家具。

当前新增家具只开放游戏原生生成。切换到联机方案时，列表会按方案过滤它们；执行层也会拒绝将动态家具交给未经验证的联机生成路径。家具列表同时补充了地面对象生成路径，但实际存档内的地面拾取和家具放置尚未验证。

## 原因和实现

原列表只读取 `ScriptManager.getAllItems()`。家具部件往往使用 `Moveables.<图块名称>` 动态创建，没有独立的普通物品脚本，因此不会出现在该目录中。

现在列表额外读取已经加载的 `IsoSpriteManager` 图块名称映射，筛选 `IsMoveAble`，并逐项由游戏工厂创建及 `Moveable.ReadFromWorldSprite` 验证。名称、图标和部件信息取自游戏；同一图块类型去重，不同朝向和部件各自保留。模组注册的同类图块也使用这条扫描路径，具体可用项取决于当前游戏加载的数据。普通物品原有的隐藏、废弃过滤规则保持不变。

背包的 `ItemContainer.AddItem(String)` 会先查询普通脚本，因此不能直接接受家具动态类型。新增流程在游戏主线程调用工厂创建对象，再执行 `AddItem(InventoryItem)`，并验证返回物品的背包归属。每个数量单位分别创建对象，避免复用同一家具实例。

## 验证

- 真实游戏 JVM 中复现了字符串 `AddItem` 无法生成动态隔间的问题，并验证工厂创建对象后加入背包成功、容器归属正确。
- 使用真实游戏图块加载器读取本机 `media/newtiledefinitions.tiles`，目录扫描得到 **6,399 个家具部件、12 个隔间部件**；此数量是该基础数据文件的结果，实际存档会随游戏版本及模组变化。
- 样本扫描验证了原有物品保留、非可移动图块排除、名称为空但映射键有效的图块、重复扫描去重、朝向保留、生成方案限制、隔板别名和普通物品搜索；家具分类文本测试通过。
- Release DLL 和启动器编译、嵌入资源一致性及分发包校验完成。

复现目录测试：

```powershell
.\scripts\test-moveable-catalog.ps1 -GameRoot '<ProjectZomboid 安装目录>' -JdkRoot '<JDK 目录>'
```

未启动游戏进入存档操作 UI，也未逐一验收全部家具的地面生成和放置效果。JVM 测试的游戏数据和 API 来自本机安装版本，不代表其他版本全部兼容。
